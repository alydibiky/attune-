## A. Engine lifecycle (items 2, 19, 20) — mostly ✅
Root cause: **the app released the model itself.** `MainActivity.onTrimMemory` freed it at level ≥ 40
(TRIM_MEMORY_BACKGROUND), which Android sends on almost every switch to the background; the reload on return ran blind
and the page threw "No model is running — open Engine" when it saw `idle`.
- ✅ `NativeBridge.wake()` (synchronised, never starts twice); `LocalEngine.waitReady` wakes instead of throwing; the chip says
  "Asleep — wakes when needed"; every tool counts an installed model as usable (`modelUsable`); `onTrimMemory` releases only
  at level ≥ 80, or ≥ 15 with the system's `lowMemory`.
- ⬜ Save/restore the open screen, the typed draft and a running job when the process is killed (page-side, localStorage on
  `attune-pause`; "Answer was interrupted — Continue").
- ⬜ Foreground-service grace period (~2 min after an answer) and the battery-optimisation prompt for Honor/MagicOS (offer it
  after the first lost answer, not at start-up). A permanent foreground service just to hold the model is NOT recommended
  (Play policy; MagicOS still kills it on swipe-away).
- ⬜ Draft model unload when backgrounded (only when the engine restarts anyway); `--load-mode none` stays (MagicOS drops
  mapped pages: 20 → < 1 t/s measured).

## B. Heat / speed (item 1) and storage ideas (item 3)
Findings: the "large model" warning used 30 % of RAM (Zenith 5.37 GB on a 16 GB phone that reports ~16.2 GB → 33 %) ✅ now 40 %.
The GPU path **half-fails**: OpenCL cannot allocate 4.37 GB (err -61), the engine carries on with GPU-mode flags (no flash
attention, f16 KV) → slower and hotter than a plain CPU start.
- ✅ After READY on GPU, a log line matching `opencl … failed to allocate` / `err=-61` → stop and start again on the CPU.
- ✅ Engine poll 10 s (1 s only while loading, none while hidden); WebView timers paused in the background (not while an answer
  runs or the model is waking).
- ⬜ Threads: test 2 / 3 / 4 / 6 with `llama-bench` on the ARM runner (`model-bench.yml`) and mAh on the phone; SM8850 has
  2 prime + 6 performance cores, `generationThreads` picks 4 (counts all 8 as "big").
- ⬜ Draft model: default off or auto-off when acceptance < 0.6; `--spec-draft-n-max 4–6`, `-td 2`, small draft ctx.
- ⬜ KleidiAI: the bench builds without `GGML_CPU_KLEIDIAI=ON` (the app has it) → add it, then compare Q4_0 vs IQ4_NL vs Q4_K_M
  (KLD ar ≤ 0.03 AND write t/s ≥ IQ4_NL, then mAh on the phone).
- ⬜ KV: cap ctx at 8K for ≥ 4 GB models; q8_0 everywhere (try q4_0 only after a KLD trial).
- ⬜ Thermal listener (`addThermalStatusListener`, `getThermalHeadroom`): at MODERATE add a pause between tokens; at SEVERE
  restart with 2 threads and no draft **between answers**. Idle unload after ~10 min (pair with a cached prompt).
- ⬜ Item 3 ranking: (1) prompt/KV cache to storage — ship (server has `--slot-save-path`, but `--no-slots` disables the API;
  or keep the system prompt short/stable for `--cache-reuse`); (2) offline knowledge packs (BM25/embedding RAG) — ship;

## C. Fit & Food photos and recipes (item 10)
Root causes: (1) `FastEngine.load` falls back to **GPU without vision**; `contentsOf` then silently drops the image, the page
still believes the model sees photos (`LocalEngine.vision` comes from `ModelStore` "any .litertlm reads photos", not the real
`fastVision`) → nothing is recognised. (2) No time limit; up to 5 vision passes in a row; grammar mode (`json:true`) sends
nothing until the end. (3) The renderer is killed for memory → `recreate()` while a GPU turn holds the semaphore.
- ✅ Every photo call has a limit (75 s first look, 30 s others, one zoom only), `abort()` on timeout, the limit starts after the
  model is awake; `canSee` from the engine's real `fastVision`; clear fallback message ("name the food instead");
  Engine log notes why photos are off; renderer-gone is logged.
- ⬜ CPU+vision fallback before GPU-without-vision (lazy `ensureVision()` that reloads once) — phone-only.
- ⬜ Shorter photo prompt: drop the 350-name list (≈ 1.8k tokens), ask for free names + Arabic, map with `matchFood` in code;
  send 768 px JPEG q0.8 instead of 1024.
- ⬜ Fallback chain with the offline reader: chips of recent foods / learned corrections / Egyptian staples → `R.readMealText`.
- ⬜ Trials: new `foodpics` section in `tests/trials/max.mjs`. Datasets reachable from the container: `ethz/food101` (HF; research

## D. File converter (item 17) — ⬜ (plan complete)
Note: the two side-by-side PNGs named in NEXT_SESSION are NOT in the repo (only the PDF and the app's docx).
Root causes, with the code: table indent from the centred cell **text** (`convert.js:367` `blk.ind = tl - g.L - 5`) and no check that
`ind + Σwidths ≤ text width`; neither PDF reader (`DocTools.kt`, `PdfLayout.java`) reads vector graphics (no fills/rules) so shading,
borders and the real table box are unknown; `DocTools.kt:213` only detects raised small words (superscript), never subscripts, and the
superscript branch `continue`s before `wordsOf.put` so italic/bold runs lose it; glyphs with no ToUnicode (macOS Quartz STIX fonts)
are dropped; paragraphs merge because the join test is only "near and same size"; a wrapped list line back at the margin becomes a new
paragraph; letter labels (a., b., c.) become a `ListBullet` list with a tab and hanging indent; `w:line` only written when pitch > 1.2×.
Ordered changes: (1) readers: add a `PathFinder` (rects/lines with fill+stroke) next to `ImageFinder` in BOTH files; (2) per-word
sub/superscript `v` field; (3) missing-glyph recovery via glyph name → `GlyphList`, else a crop for the 📷 reader; (4) tables from the
rects (`ind`, widths, row shading, alignment, borders) with a clamp so they never leave the page; (5) `docxFromBlocks` writes
`tblBorders`, `w:shd`, per-cell `jc`, cell margins; (6) runs carry `vertAlign`; (7) "previous line ended short" paragraph break;
(8) list continuation back at the margin; (9) letter labels as bold paragraph labels, no list style; (10) exact line pitch.
Bench: `tests/convert/fixtures/real/<name>.pdf` + `<name>.expect.json` scored by a new `real.py` (table box ±3 pt, shading, alignment,
sub/sup tokens, paragraph starts, bold labels, no `�`, word positions ±2 pt, page-picture difference); add an Arabic CV, an invoice, a
report with maths. Tools: java, soffice, poppler present; `pip install python-docx pdfplumber pypdfium2`; the PDFBox jar is fetched by
`run.sh`. Other formats after PDF→Word: Word→PDF (carry the same fields), RTF and ODT (readers keep only text), PPTX scoring, Excel styles.
