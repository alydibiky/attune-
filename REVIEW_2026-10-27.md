## C. Web search — "fix it for good" (Ali's item 1)

Fixed in v8.4 (by code, tested): the maker's country is a fact the app knows (Lynk & Co = China, Geely) — told to the model and
corrected in the answer; lines that only say "prices are available" without a price are removed; a sentence cut in half is removed;
the trims-table instruction can't become an extra column any more; an answer written without web pages gets the same clean-up
(empty columns dropped, citations to nothing removed).

The deeper problem: a small phone model reading 10 messy web pages. Three ways to fix it for good:

- **Option A (recommended) — "Code builds the table, the model only talks."** For cars (then phones, cranes): Attune reads known spec
  sites (auto-data.net, ultimatespecs, carnewschina; hatla2ee / contactcars for Egypt prices) with a small reader per site, and
  fills the trims / specs / prices tables itself — exact numbers, every trim, with the site name. The model writes only the
  overview, pros and cons. Fast on any phone, numbers can't be invented. Cost: a reader per site (kept up to date when a site changes).
- **Option B — "Strong brain online, only for web answers."** You add your own Gemini or Claude key; web questions go to it, every
  thing else stays on the phone. Answers as good as Gemini's, but it costs per question and the question leaves the phone.
- **Option C — "Check every sentence."** After the answer, code checks each sentence's claim against the page it cites, and a
  second short pass rewrites what doesn't match. Works for any topic, but adds 20–40 s per answer on a phone.

My recommendation: **A first** (cars, phones, cranes = most of your questions), with **B as a switch** for people who want it.

## D. Voice (Ali's item 5)
v8.4: when the phone's own recogniser refuses other apps (common on Honor / Huawei / Xiaomi), Attune now asks **Google's recogniser
by name**, and if that also fails it opens **Android's own voice-typing popup** (works whenever the Google app or "Speech Services
by Google" is installed). Every try writes a line to the log ("Voice (time): listening: … / error N / opened Android's voice popup").
If it still fails: send the log — the "Voice" lines say exactly which step failed.
